# Test File Conventions

These rules apply when working with any file in `tests/`.

## Import

Always import from the custom fixture — never from `@playwright/test` directly:

```typescript
// Correct
import { test, expect } from '@fixtures/site.fixture';

// Wrong
import { test, expect } from '@playwright/test';
```

## Tagging

Every `test()` call must include at least one tag. Tags appear in the test title string:

```typescript
test('homepage hero is visible @smoke @functional', async ({ homePage }) => { ... });
```

Available tags:
- `@smoke` — fast availability checks
- `@navigation` — links, routing, menus
- `@forms` — form fields and validation
- `@functional` — business features and logic
- `@visual` — screenshot regression
- `@responsive` — viewport-specific layout
- `@custom` — site-specific tests generated by agents

## Structure

```typescript
test.describe('Feature Name @tag', () => {
  test.beforeEach(async ({ page, siteConfig }) => {
    await page.goto(siteConfig.url, { waitUntil: 'domcontentloaded' });
  });

  test('specific behavior @tag', async ({ homePage, siteConfig }) => {
    // Use page object methods, not raw page.locator()
    const heading = await homePage.getMainHeading();
    expect(heading.length).toBeGreaterThan(0);
  });
});
```

## Rules

- Use page object methods — not raw `page.locator()` in test bodies
- Use `siteConfig.url` — never hardcode `http://www.flagshipfleet.com`
- Never submit forms
- Never call `page.waitForTimeout()` — use `await expect(locator).toBeVisible()` or Playwright auto-waiting
- Keep each test independent — no shared mutable state between tests
- Use `test.skip(condition, 'reason')` rather than commenting out tests
- If a page feature may not exist on all sites, guard with `if (count > 0)` and log a warning rather than hard-failing
- Prefer `expect(value, 'descriptive failure message').toBe...` — always include a failure message
